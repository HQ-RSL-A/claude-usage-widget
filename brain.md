## Architecture Decisions

- **AppKit only** - lighter weight, better NSStatusItem control than SwiftUI
- **OAuth token instead of the session cookie** (v0.4.0) - the real browser does the signing in (Google, passkeys, autofill work); usage comes from `api.anthropic.com/api/oauth/usage` with the same body shape as the claude.ai web endpoint
- **Identity order** - own OAuth token, then Claude Code's token, then the v0.3.0 web session, else signed out. The user chose the browser route explicitly, so it wins; Claude Code's is a convenience; the web session is the upgrade path and the fallback
- **Never refresh Claude Code's token** - rotating it would break Claude Code; the widget re-reads the current access token on every poll
- **Honest User-Agent** - Cloudflare rejects only anonymous-looking clients (Python's default); `ClaudeUsageWidget/<version> (macOS)` passes
- **Keychain denial remembered** - `claudeCodeTokenDenied` in UserDefaults, cleared only by "Use Claude Code's sign-in"; existence is probed with an attribute-only query that never prompts
- **Claude Code's token read through `/usr/bin/security`** (v0.5.1) - Claude Code writes its item with that tool, so the item trusts it and macOS never asks for the Mac password. Reading it with SecItem asked at every launch: each Claude Code token refresh rewrites the item and resets its partition list to `apple-tool:`, dropping "Always Allow" for every other app, and each update of this ad-hoc signed app has a new cdhash. `find-generic-password -s "Claude Code-credentials" -w`, 10 s timeout, exit 44 = not found, any other failure counts as denied
- **Web session kept one release** - the borrowed OAuth client id could be blocked; the embedded login still works
- **JS bridge over URLSession for the web session** - claude.ai's bot protection tends to reject non-browser clients
- **Outside click closes the popover** (v0.4.2) - `.transient` alone does not do it for a menu bar app, because the app is never active and AppKit never sees the dismissing click. `OutsideClickDismisser` arms a global mouse-down monitor in `popoverDidShow` and disarms it in `popoverDidClose`. Global monitors never see this app's own clicks, so the popover's controls and the status item behave as before
- **Both limits in the menu bar** (v0.5.0; replaced in v0.6.0 by one logo and the lowest limit, see "One panel for three services" and "Menu bar item, v0.6.0" below) - two rings, session left and week right, each with what's left inside (`100 - round(used %)`, so it adds up with claude.ai's "% used"). The arc fills with what's used. Rahul asked for rotating numbers; both at once won (no waiting, no motion). A missing bucket keeps its slot as a dimmed dash so the width never changes
- **Readable on any wallpaper** (v0.5.0, Rahul; the rings are gone in v0.6.0, the rule is not: the title is the system's own text and only the badge dot is colored) - digits and tracks use the menu bar's color, only arcs are amber or red. All-normal rings render as a template image; once an arc is colored the image is not a template, so normal parts are drawn white or black from `NSAppearance.currentDrawing()` inside the drawing handler (`cacheMode = .never`). macOS draws the item once per display in that menu bar's appearance, so one image is right on every display
- **Nothing observes the appearance; the status item changes only when its content does** (v0.5.1) - v0.5.0 re-set the image whenever the button's `effectiveAppearance` changed, but macOS sets that appearance on every redraw of every display's copy (`_redrawReplicantSnapshot` -> `setAppearance:`), so the image was re-set forever: 80 to 87% CPU, WindowServer at 40%+, flagged by the battery menu. `StatusItemRenderer` applies image, tooltip and VoiceOver value only when each changed
- **Never stale at full strength** - the menu bar re-renders every 60 s; numbers older than their service's clock dim (`ServiceState.isCurrent`); Claude fetches 10 s after the earliest reset and on wake from sleep
- **One panel for three services** (v0.6.0, Rahul: "it always stays logged in", "view all the other LLMs' usages with their icons", "easy to read") - Claude, Grok Bot, Codex; not Antigravity. The menu bar shows the limit closest to running out across the shown services with that service's logo, or one service the "..." menu pins; a pin that is hidden, signed out or empty falls back to the lowest, never a dead item. A budget (Claude's extra usage) is shown in the panel and never picked for the menu bar
- **Menu bar item, v0.6.0** - the service's mark plus "N% remain" in the system's own menu bar text (`StatusIcon.titleFont`, digits of one width). Only a 6 pt badge dot on the logo turns amber or red (the 2026-10-26 rule: colored digits get lost on colored wallpapers). The width is fixed: the status button centers whatever it holds, so every title is padded on the right with figure spaces (U+2007) to the width of "100% remain" and the text is aligned left; a trailing kern does nothing because the text system drops it. `appearsDisabled` dims the image and the title together, colored or not. "Sign in" is a call to action, so it is not dimmed (dimmed it was 2.6:1 on a light bar); stale numbers, "Updating" and "Offline" are
- **One rule for "current"** - `ServiceState.isCurrent(_:now:)` is the only place that decides a reading is old, and the menu bar and the panel both call it. A reading is old when it is older than its service's clock (Claude and Codex 15 min, three missed polls; Grok Bot 24 h, because its numbers only move when its Mac app refreshes them) or when a non-budget limit has reset since (it may be from before the reset). A not-current reading never beats a current one in the menu bar; alone it shows dimmed, and VoiceOver says "out of date"
- **Hidden services are not read, Claude included** - `ServicesPoller.isEnabled`, asked just before each read, is set from `ServiceSettings`: a hidden Codex never sends its token to ChatGPT. Showing a service again triggers `poller.refresh()`. Claude is gated in `AppDelegate`: hiding it stops its `UsageService` (no 5-minute poll, no fetch on wake, refresh or open), showing it again restarts it with a fetch at once when signed in, and a launch with Claude hidden never starts it. The last shown service cannot be hidden. The shown list is always `[.claude] + poller.setUpServices()` minus the hidden ones, never derived from the keys of a states dictionary; a set-up service the poller has not read yet is `.loading`
- **Grok Bot and Codex are read, never run** - Grok Bot from two of the files its Mac app saves; Codex from its `auth.json` token and ChatGPT's usage endpoint. Neither token is refreshed, written, stored or logged. Claude keeps its own sign-in and polling
- **No token on disk** (v0.6.0) - `URLSession.shared` stores every request, headers and bearer token included, in `~/Library/Caches/<bundle id>/Cache.db`, and a cache policy on the request only skips reading it. Every request now goes through `HTTP.session` (ephemeral, 30 s cap on the whole request) with `Cache-Control: no-store`, and `HTTP.purgeCachedResponses()` empties the old cache once at launch before any request. On Rahul's Mac the v0.5.1 cache held 40 rows (the v0.6.0 review found them); after the first v0.6.0 launch all three cache tables have 0 rows and `Cache.db` and its WAL hold no "Bearer" or "api.anthropic.com" text
- **Panel colors** (v0.6.0) - amber and red numbers are `#F59E0B` and `#EF4444` on a dark panel and `#B45309` and `#DC2626` on a light one (the menu bar's amber is about 2:1 on white), picked while drawing by a dynamic `NSColor`. Notes and the footer's status line use the secondary label color (tertiary measured 1.9:1 on light; the version stays tertiary). The menu bar's colors did not change
- **Panel redraws only what changed** - `MenuViewController.reload` works out `[PanelSection]` (plain values: rows, note, sign-in prompt, dimming) on every state change and every clock tick (60 s, and 30 s while the panel is open), and `draw` compares it with the last one drawn. The same services in the same order: only the sections that differ are replaced in place (the rest keep their views, so VoiceOver's place and a click in progress survive); anything else, or an icon swap, rebuilds all. Numbers and a failure belong to a sign-in: any state but `.signedIn` clears them, so the next sign-in (maybe another account) starts at "Loading..." and never shows the last one's numbers
- **Panel icons** - the Mac app's own icon by bundle id (`NSWorkspace`), looked up once per service per launch (`PanelIconCache`: an app icon carries about 32 images up to 2048 px). Without the app, a tile in the service's color with its mark in white, on the same 824/1024 grid as a real app icon
- **No keyboard shortcuts in the popover** - the app never activates, so key presses go to the app in front; activating on open would steal focus at every glance
- **Core Graphics drawing**, **5-minute polling**, **main actor everywhere**, **`main.swift` detects XCTest**, **version from `project.yml`** (unchanged since v0.3.0)

## Auth Flow (v0.4.0)

`AuthState`: `unknown` -> `unreachable` | `signedOut(claudeCodeAvailable)` | `signingIn` | `signedIn(IdentitySource, Profile?)` | `sessionExpired(IdentitySource)` | `noChatOrg`.

1. Launch: `AuthManager.checkAuthStatus()` probes whether Claude Code's Keychain item exists (no prompt), then tries, in order: own token (`KeychainTokenStore`; refreshed if within 5 minutes of expiry; a refused refresh clears it), Claude Code's token (read through `/usr/bin/security`, no prompt; `isValid` means more than a minute left), the web session (only if `webSessionEnabled`, which is set automatically when v0.3.0 cookies exist). Nothing -> `signedOut`
2. Browser sign-in: PKCE + state, `CallbackServer` on a free localhost port, authorize URL opened in the default browser, one `GET /callback`, code exchanged at the token endpoint, `TokenSet` saved, then `checkAuthStatus()` again. Cancel or 5-minute timeout -> `signedOut` with `signInMessage`
3. Polling: `OAuthUsageSource` asks the provider for a bearer token (own token refreshed when due), one 401 triggers one refresh and one retry, a second 401 is expiry. `UsageService` stops and `AuthManager.sessionDidExpire()` maps to `sessionExpired(source)` (own token cleared)
4. Sign Out: own token deleted, `claudeCodeTokenOptOut` set, web session wiped if it was enabled, state `signedOut`
5. Transport failure or 5xx while resolving -> `unreachable`, retried every 60 s

### UserDefaults keys

`claudeCodeTokenOptOut` (set by Sign Out), `claudeCodeTokenDenied` (set when the Keychain prompt is denied), `webSessionEnabled` (set by "Sign in inside the app" or by the v0.3.0 upgrade), `hiddenServices` (array of service ids the "..." menu hid), `menuBarService` (`lowest` or a service id). `ringMetricMode` (v0.2.0 to v0.4.2) and `menuBarShows` (v0.5.0 and v0.5.1) are deleted at launch by `ServiceSettings.removeLegacyKeys`, not migrated.

## OAuth (verified 2026-10-12)

- Authorize: `https://claude.com/cai/oauth/authorize` with `code=true`, `client_id=9d1c250a-e61b-44d9-88ed-5944d1962f5e` (Claude Code's public client; no third-party registration exists), `response_type=code`, `redirect_uri=http://localhost:<port>/callback`, `scope=user:profile user:inference`, `code_challenge` (S256), `state`
- `state` length matters: 22 characters (16 bytes) is refused at the Authorize click with "Authorization failed / Invalid request format"; 32 and 43 characters are accepted. The consent page loads either way, and URL encoding (`%20` or `+`, encoded or plain `redirect_uri`) makes no difference. The app sends 32 bytes
- Token: `POST https://platform.claude.com/v1/oauth/token`, JSON `{grant_type: authorization_code, code, state, client_id, redirect_uri, code_verifier}` or `{grant_type: refresh_token, refresh_token, client_id}` -> `{access_token, refresh_token, expires_in: 28800, refresh_token_expires_in, scope, token_type, token_uuid, account, organization}`; 400 `{error, error_description}` when refused; Cloudflare 403 error 1010 for anonymous User-Agents
- Usage: `GET https://api.anthropic.com/api/oauth/usage` (Bearer) -> same shape as the web endpoint (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `extra_usage`, codenamed nulls, plus a `limits` array); 401 without a valid token
- Profile: `GET https://api.anthropic.com/api/oauth/profile` -> `{account: {email, display_name, full_name, has_claude_max, has_claude_pro}, organization: {name, organization_type, rate_limit_tier, ...}}`
- Headers on every request: `anthropic-beta: oauth-2025-04-20`, `User-Agent: ClaudeUsageWidget/<version> (macOS)`, `Accept: application/json`
- Claude Code's Keychain item: generic password, service `Claude Code-credentials`, JSON `{claudeAiOauth: {accessToken, refreshToken, expiresAt (ms since epoch), refreshTokenExpiresAt, scopes, subscriptionType, rateLimitTier}}`. Its access list (checked 2026-11-04 with `security dump-keychain -a`, no secrets): decrypt trusts `/usr/bin/security` only (old widget cdhashes linger but fail), partition list `apple-tool:`. Claude Code rewrites it in place on every token refresh (creation date kept, modification date moves)

## Web session API (v0.3.0 fallback, verified 2026-10-12)

`GET /api/organizations` (array; `capabilities` contains `chat` for consumer orgs), `GET /api/organizations/{uuid}/usage`, error envelope `{"type":"error","error":{"type","message","details":{"error_code"}}}`; no session is HTTP 403 with `error_code: account_session_invalid`, a bare 403 is per-org, `lastActiveOrg` is a readable cookie.

## Grok Bot (verified 2026-11-04 on Rahul's Mac)

Files are in `~/Library/Application Support/Grok Bot/sand-client-persistence/`. Each is named with the RFC 4648 base32 of its key, lowercase, no padding, plus `.blob`. The widget opens two of them and nothing else; never `sand-secrets.json` and never the "Grok Bot Safe Storage" Keychain item.

- Account slot: key `sand.client.slice.client-meta.account-slot`, file `onqw4zbomnwgszlooqxhg3djmnss4y3mnfsw45bnnvsxiyjomfrwg33vnz2c243mn52a.blob`, content `{"schemaVersion":1,"value":"<slot>"}`
- Usage: key `sand.client.slice.account.<slot>.weekly-usage.cache`, content `{"schemaVersion":2,"value":{"kind":"present","reading":{"usage":{"percentUsed":7.04,"nextResetMs":1794345715756,"hasNonZeroIncludedLimit":true,...},"readAtMs":1793824425618},"expiresAtMs":...}}`. `percentUsed` is 0 to 100. Grok Bot rewrites the file when its own window refreshes, not on a timer, and its own time to live is 24 h
- **The slot is stored as typed but spelled escaped in the file name.** The account-slot blob holds `google-oauth2|<id>`; the usage file's name has `google-oauth2%7C<id>` (a browser's `encodeURIComponent`). The first build read the slot "as saved, already escaped" (the spec's assumption) and found no file, so the panel told Rahul to open Grok Bot while his 93% was sitting there. `GrokBotReader.fileNameSlot(for:)` escapes it; a slot saved already escaped is still found as saved. Only caught by the real-data pass, never by fixtures written from the spec
- Real reading that day: 7.04% used (93% left), resets Tue Nov 10 at 1:21 PM, read at 12:33 PM. A reading is days old whenever he has not opened Grok Bot (he mostly uses it on his phone), so the panel says "Updated N days ago" and the menu bar dims it after 24 h
- A usage file that is missing or not `kind: present` says "Open Grok Bot to load its usage"; a missing or empty slot says "Open Grok Bot and sign in"; a new schema version says "Grok Bot changed how it saves usage"; `hasNonZeroIncludedLimit: false` says "No included usage on this plan"

## Codex (from CodexBar, MIT, `steipete/CodexBar`, `docs/codex.md`; never run live: Codex is not installed and OpenAI was cancelled 2026-10-30)

- Auth file: `$CODEX_HOME/auth.json`, else `~/.codex/auth.json`, with `tokens.access_token` and `tokens.account_id`. Read fresh on every poll, never written, never kept. A file with only an API key says "Sign in to Codex with ChatGPT". Codex in keyring mode has no `auth.json`, so no Codex section; `CODEX_HOME` set in a shell profile is not seen by a Finder launch
- Request: `GET https://chatgpt.com/backend-api/wham/usage` with `Authorization: Bearer <access_token>` and `ChatGPT-Account-Id: <account_id>`, through `HTTP.session`, `Cache-Control: no-store`
- Response: `rate_limit.primary_window` and `secondary_window`, each with `used_percent` (0 to 100), `limit_window_seconds` and `reset_at` (epoch seconds). A window of 6 hours or less is the "5hr Session", a longer one is "Weekly"
- Never refresh the token; Codex owns `auth.json`. 401 or a JSON 403 says "Open Codex to refresh its sign-in". A 403 with a body that is not JSON (Cloudflare's page or its plain "error code: 1010") is not the token being refused, so it says "Couldn't reach Codex"
- Unverified against live ChatGPT. If Cloudflare ever refuses the widget's User-Agent, the panel says "Couldn't reach Codex"

Run a new SVG through `CORESVG_VERBOSE=1` and compare it with `rsvg-convert` before adding it to the catalog

## Menu Bar

The item is the service's mark, then "N% remain" (what's left, `100 - round(used %)`, so it adds up with the "% used" of claude.ai). Hover for every limit of every shown service with its reset time, and how old a reading is once it is over 15 minutes old. VoiceOver: the item is "Usage Remaining" and its value is "Grok Bot Weekly, 40% remaining", with ", out of date" when dimmed.

| Used share | Badge dot on the logo |
|------------|-----------------------|
| under 60% | none (the mark is a template, tinted by the system) |
| 60 to 84% | Amber (#F59E0B) |
| 85% and up | Red (#EF4444) |

With no number the item says why, dimmed except "Sign in": "Sign in" (signed out, session expired, no Claude plan; Grok Bot or Codex not signed in), "Updating", "Offline", "No data" (a reading with no limit in it). Ties go to the earlier service in panel order, then the earlier limit, comparing the number the bar would show. The panel is "Usage Remaining" with one section per shown service: the icon, then rows of label, what's left ("93%") and the reset ("2:10 PM" under a day away, "Nov 10" beyond; the tooltip has the full "Resets Tue Nov 10, 1:21 PM"). A non-Claude reading over 15 minutes old gets "Updated 2 hr ago" (days from 24 h) under its rows; Claude's age is in the footer. A row is one sentence to VoiceOver ("Weekly, 93% left, Resets Tue Nov 10, 1:21 PM"), with ", out of date" added when its numbers are dimmed. When claude.ai cannot be reached the Claude section says "Could not reach claude.ai" and "Check your connection. It tries again every minute." (the retry is `AuthManager.unreachableRetryInterval`, 60 s). The "..." menu: Refresh, Menu Bar Shows (Lowest Remaining or one shown service), Show (each set-up service, the last shown one disabled), Open at Login, Sign Out of Claude (only with a sign-in), Quit.

## Testing

- `xcodebuild test -scheme ClaudeUsageWidget -destination platform=macOS CODE_SIGNING_ALLOWED=NO` (380 tests as of v0.6.0); CI runs the same on every push to `main`. The version tests (`ClaudeUsageWidgetTests`, `ClaudeAPIErrorTests`) pin `MARKETING_VERSION`: bump them with `project.yml`. Tests never read real files under `~/Library` or `~/.codex`: readers take a temp folder, the cache purge takes a cache of its own, Keychain tests use `io.rsla.ClaudeUsageWidget.tests*`
- **Preview mode:** `open -n ClaudeUsageWidget.app --args -previewUsage amber` (also `fresh`, `normal`, `critical`, `limit`, `stale`, `signedOut`) shows made-up numbers for all three services in the real menu bar and panel with no sign-in, Keychain, WebKit, file read or network request, so a fresh build raises no Keychain prompt. `stale` has a Grok Bot reading 26 h old and an unreachable Codex; `signedOut` has Claude signed out, Grok Bot and no Codex section. It shares the installed app's preferences (`hiddenServices`, `menuBarService`), so quit the installed copy first and reopen it after
- System Events reads the item: `help` is the tooltip, `description` the VoiceOver label; while open, the popover is an `AXPopover` child of the menu bar item
- `StubURLProtocol` answers OAuth requests; `FakeClaudeAPI` scripts web-session responses; `FakeCallbackServer`, `InMemoryTokenStore`, `FakeClaudeCodeCredentials` drive the coordinator; `CallbackServerTests` make real localhost requests; one Keychain round trip runs under `io.rsla.ClaudeUsageWidget.tests`, one `/usr/bin/security` round trip under `io.rsla.ClaudeUsageWidget.tests.claudecode`; `FakeProcessRunner` scripts the tool's endings
- The popover can be driven for real through Accessibility, never by screen position (Rahul uses the Mac): `tell process "ClaudeUsageWidget"` in System Events, `perform action "AXPress" of menu bar item 1 of menu bar 1` opens it and the same call closes it; while open it is a `pop over` child of the item, and its `entire contents` gives every row's text (`Weekly, 93% left, Resets Tue Nov 10, 1:21 PM`) and frame. The item's `help` is the tooltip, `value` the VoiceOver value, `description` its label.
