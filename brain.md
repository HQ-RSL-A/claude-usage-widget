## Architecture Decisions

- **AppKit only** - lighter weight, better NSStatusItem control than SwiftUI
- **WKWebView with persistent data store** - `WKWebsiteDataStore.default()` keeps the user signed in across restarts; the app never reads the session cookie
- **JS bridge over URLSession** - same-origin `fetch` from a hidden WKWebView on claude.ai; claude.ai's bot protection tends to reject non-browser clients. Every call returns `{status, body}` and `ClaudeAPIError.classify` is the one place status is interpreted
- **Signed in is proven by the API** - a 2xx from `/api/organizations`; cookie presence proved nothing (expired or abandoned logins leave cookies behind)
- **Chat-org picker** - the `lastActiveOrg` cookie's org if it can chat, else the first `chat`-capable org, else "no Claude plan"; API console orgs always 403 on usage
- **Rows from buckets** - every usage bucket is optional; the popover draws whatever came back (Session, Weekly, Opus, Sonnet, Extra usage)
- **Core Graphics ring** - custom `NSView`, no third-party libraries
- **5-minute polling** - `Timer.scheduledTimer` + manual refresh available
- **Main actor everywhere** - WebKit and AppKit require it; `AppDelegate`, `AuthManager`, `UsageService`, `ClaudeAPIClient` are `@MainActor`
- **`main.swift` detects XCTest** - minimal `TestAppDelegate` avoids full UI launch during tests
- **Ring metric toggle** - `RingMetricMode` enum (`.session` / `.weekly`) persisted in `UserDefaults`
- **Version from `project.yml`** - `MARKETING_VERSION` flows into Info.plist and the popover footer

## Auth Flow

`AuthState`: `unknown` -> `unreachable` | `signedOut` | `signedIn(org, chatOrgCount)` | `sessionExpired` | `noChatOrg`.

1. Launch: `AuthManager.checkAuthStatus()` -> `GET /api/organizations` through the hidden webView (which first loads claude.ai once; signed out it lands on `/login`, same origin, fetches still work)
2. 2xx -> pick the chat org -> `signedIn` -> `UsageService(client, orgId).start()`. No chat org -> `noChatOrg`. Session invalid -> `signedOut` and the login window opens. Transport or 5xx -> `unreachable` (popover offers refresh)
3. Login window: KVO on the URL and `didFinish` only *trigger* `verifySession()`; a 2 s fallback timer also calls it while the window is open. The window closes when the API returns `signedIn` or `noChatOrg`, never on URL shape
4. Polling: a 403 `account_session_invalid` on usage stops the service and calls `AuthManager.sessionDidExpire()` -> `sessionExpired`, login window opens once per expiry (closing it by hand does not reopen it; the popover's Sign In does)
5. Sign Out: wipes `WKWebsiteDataStore.default()`, `client.reset()` (next call reloads claude.ai), `signedOut`, login window

### Google OAuth Caveat

`SOAuthorizationCoordinator` can block Google sign-in in unsigned WKWebView apps. The `WKUIDelegate` popup handler covers most cases, but Google may reject at the final redirect. Workaround: email code or email/password login (HQ-113, HQ-117).

## API (verified live 2026-10-12)

All calls are same-origin `fetch` from a WKWebView that has loaded a claude.ai page.

**`GET /api/organizations`** -> 200, JSON array. Used fields: `uuid`, `name`, `capabilities` (`chat` = consumer org; `api`, `api_individual` = console org), `rate_limit_tier` (e.g. `default_claude_max_20x`), `plan_display_name` (nullable). Order is not documented.

**`GET /api/organizations/{uuid}/usage`** -> 200, object. Every bucket nullable, same shape: `{utilization: 0..100, resets_at: ISO8601, limit_dollars, used_dollars, remaining_dollars, locked_reason}`.
- Decoded: `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `extra_usage.{is_enabled, utilization}`
- Ignored: `seven_day_oauth_apps`, `seven_day_cowork`, ~15 codenamed buckets (`iguana_necktie`, `tangelo`, ...), `limits`, `spend`, `seven_day_breakdown`, `weekly_scoped_shares`, `member_dashboard_available`

**Errors** share one envelope: `{"type":"error","error":{"type":"...","message":"...","details":{"error_code":"..."}},"request_id":"..."}`

| Situation | Status | `error.type` | `details.error_code` |
|---|---|---|---|
| No session / invalidated | 403 | `permission_error` | `account_session_invalid` |
| Valid session, console org usage | 403 | `permission_error` | absent ("Permission denied.") |
| Unknown org | 404 | `not_found_error` | absent |

**Cookies:** `lastActiveOrg` (readable, value = org uuid) drives org selection. `sessionKey` is HttpOnly and never read.

## Ring Color States

| Usage % | Color |
|---------|-------|
| 0 to 59% | Monochrome (adapts to light/dark menu bar) |
| 60 to 84% | Amber (#F59E0B) |
| 85 to 100% | Red (#EF4444) |

Ring shows session usage by default, configurable via popover toggle. Weekly mode shows the highest of the weekly buckets. Any state other than signed in shows an empty ring.

## Testing

- `xcodebuild test -scheme ClaudeUsageWidget -destination platform=macOS CODE_SIGNING_ALLOWED=NO` (71 tests as of v0.3.0); CI runs the same on every push to `main`
- `FakeClaudeAPI` scripts responses per call; `Fixtures` holds the real response shapes (Max 20x usage, two-org list, every error envelope)
- Manual pass before a release: fresh sign-in via email code, sign out and back in, forced expiry, offline launch (plan Task 8)
