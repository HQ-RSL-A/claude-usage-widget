# v0.5.0 Both Limits in the Menu Bar: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The menu bar shows what's left of the session and of the week as two small rings with numbers, and the popover gets the fixes listed in the spec.

**Architecture:** Pure pieces first, each with its own tests: `UsageText` turns usage into plain words, `StatusPresentation` turns (auth state, data, layout, time) into a `StatusIconModel` plus tooltip and VoiceOver text, and `StatusIcon` draws the model. `UsageService` learns about fetch state and reset times, `OpenAtLogin` wraps `SMAppService`, `MenuViewController` drops the segmented control for a gear menu, and `AppDelegate` only wires them together. A `-previewUsage <scenario>` launch argument feeds made-up data so the real menu bar can be checked without touching the Keychain.

**Tech Stack:** Swift 5.9 language mode, AppKit, ServiceManagement (`SMAppService`, macOS 13), SF Symbols, XCTest, xcodegen.

**Spec:** `docs/plans/2026-10-26-v0.5.0-menu-bar-numbers-design.md`

## Global Constraints

- Deployment target stays `macOS 13.0`.
- `project.yml` is the source of truth. After adding or removing a source file run `xcodegen generate` and commit the regenerated `.xcodeproj`.
- `setupStatusItem()` still runs before any WebKit object exists. Preview mode creates no WebKit object and reads no Keychain item.
- Tests never touch the real Keychain items and never register a real login item (fakes only).
- What's left = `100 - round(used %)`, clamped to 0...100. Color thresholds on the used share are unchanged: under 0.60 normal, 0.60 to under 0.85 amber, 0.85 and up red.
- No motion in the menu bar. The menu bar item's width depends only on the layout, never on the numbers.
- Copy: plain everyday words; menu items in title case ("Open at Login"); labels and status text in sentence case; no en or em dash characters in UI strings, docs or commit messages.
- Test command: `DD=/private/tmp/claude-501/-Users-rahullalia-Developer-my-business-internal-tools-claude-usage-widget/017d2059-49dd-4b34-9043-d62d1fca0396/scratchpad/DerivedData` and `xcodebuild test -scheme ClaudeUsageWidget -destination platform=macOS -derivedDataPath $DD CODE_SIGNING_ALLOWED=NO`. Narrow with `-only-testing:ClaudeUsageWidgetTests/<Class>` while iterating.
- Commits: conventional prefix, end with the session's two attribution lines.

## Review Focus

1. The menu bar turns light (wallpaper or appearance change) while one ring is amber: the normal ring and its number must turn dark too, not stay white. Pinned in Task 3 (`test_image_mixedColors_drawsNormalRingInMenuBarForeground`).
2. A user clicks refresh several times quickly: one request goes out. Pinned in Task 4 (`test_fetch_whileFetching_isIgnored`).
3. The popover stays open for a long time: reset countdowns and "Updated" move with the clock. Pinned in Task 6 (`test_renderTimes_usesTheCurrentTime`).
4. Signed out, or polling has failed for a while: the menu bar must not show confident numbers. Pinned in Task 3 (`test_signedOut_showsDimmedDashes`, `test_staleData_isDimmed`).
5. A fresh session (100 left) or a maxed one (0 left): the item keeps its width and the number still fits. Pinned in Task 3 (`test_size_dependsOnlyOnRingCount`).

### Task 2: UsageText, the plain words

**Files:**
- Create: `ClaudeUsageWidget/UsageText.swift`
- Test: `ClaudeUsageWidgetTests/UsageTextTests.swift`

**Interfaces:**
- Consumes: Task 1.
- Produces: `struct UsageText { var now: Date; var calendar: Calendar; var locale: Locale; init(now: Date = Date(), calendar: Calendar = .current, locale: Locale = .current) }` with
  - `func reset(_ bucket: UsageBucket) -> String?`
  - `func detail(_ bucket: UsageBucket) -> String`
  - `func percentLeft(_ bucket: UsageBucket) -> String`
  - `func age(of date: Date) -> String`
  - `func status(lastUpdated: Date?, isFetching: Bool, failure: String?) -> String`
  - `func tooltip(for data: UsageData) -> String`
  - `func accessibilityValue(for data: UsageData) -> String`

Rules (the tests pin them):
- `reset`: nil without a future `resetsAt`. Under 24 hours: minutes = `max(1, Int((seconds / 60).rounded()))`, then "Resets in 42 min", "Resets in 2 hr", "Resets in 3 hr 10 min". 24 hours or more: "Resets " + date formatted from template `"EEEjmm"` in `locale` and `calendar.timeZone` ("Resets Thu 4:00 PM").
- `detail`: at the limit, "Limit reached, " + the reset text with a lowercase first letter, or "Limit reached" without one; otherwise the reset text or "".
- `percentLeft`: "88% left".
- `age`: under 60 s (or negative) "just now", under an hour "3 min ago", else "2 hr ago" (whole units, rounded down).
- `status`: fetching -> "Updating..."; failure with data -> "Couldn't refresh: <failure>. Last updated <age>."; failure without data -> "Couldn't refresh: <failure>"; data -> "Updated <age>"; neither -> "".
- `tooltip`: one line per bucket in `data.buckets` order, "<label>: <N>% left" plus ", <reset with lowercase first letter>" when there is one, then "Updated <age>". No buckets: "No usage limits reported" then the updated line.
- `accessibilityValue`: "Session 88% left, week 26% left" from `sessionBucket` and `weekBucket`, either part left out when missing; neither: "No usage limits reported".

### Task 3: The menu bar item: model, presentation, drawing

**Files:**
- Create: `ClaudeUsageWidget/StatusIcon.swift`, `ClaudeUsageWidget/StatusPresentation.swift`
- Test: `ClaudeUsageWidgetTests/StatusIconTests.swift`, `ClaudeUsageWidgetTests/StatusPresentationTests.swift`

**Interfaces:**
- Consumes: Tasks 1 and 2, `AuthState`.
- Produces:
  - `struct StatusIconModel: Equatable { enum Ring: Equatable { case usage(left: Int, used: Double, color: RingColorState); case noData }; var rings: [Ring]; var isDimmed: Bool; var isTemplate: Bool }` (`isTemplate`: no ring is amber or red)
  - `enum StatusIcon { static func size(for: StatusIconModel) -> NSSize; static func image(for: StatusIconModel, darkMenuBar: Bool) -> NSImage }`
  - `struct StatusPresentation: Equatable { var icon: StatusIconModel; var toolTip: String; var accessibilityValue: String; static let staleAfter: TimeInterval = 900; static func make(state: AuthState, data: UsageData?, layout: MenuBarLayout, text: UsageText) -> StatusPresentation }`

Rules:
- Signed in with data: `.both` -> always two rings, the `sessionBucket` ring or `.noData`, then the `weekBucket` ring or `.noData`; `.session` / `.week` -> that bucket's ring or `.noData`. Ring = `.usage(left: percentLeft, used: percentUsed, color: barColorState)`. `isDimmed` when `text.now - data.lastUpdated > staleAfter` or when every ring is `.noData`. A `.noData` ring is always drawn dimmed, whatever `isDimmed` says. Tooltip and value from `UsageText`.
- Every other case: `.noData` rings, two for `.both` and one otherwise, dimmed. Tooltip "Claude Usage: <phrase>" and value "<Phrase>": unknown "checking sign-in", unreachable "can't reach claude.ai", signedOut "not signed in", signingIn "waiting for your browser", sessionExpired "session expired", noChatOrg "no Claude plan on this account", signed in without data "updating".
- Drawing (sizes are the spike's, adjust by eye in Task 8): ring slot 20 x 20 pt, 3 pt between rings, radius 8.6, stroke 2.0, round caps, track at 25% of the ring color, arc clockwise from 12 o'clock with length = used share. Number: rounded bold monospaced digits, 9 pt for one or two digits, 7.5 pt for three, centered on the cap height. No data: a 5 pt drawn line, 1.6 pt thick. Dimmed: everything at 45% opacity. Normal color is black in a template image; in a non-template image it is white when `darkMenuBar`, else black.
