# v0.4.0: Sign in Through the Browser

**Date:** 2026-10-12
**Status:** Draft, awaiting Rahul's review
**Tracks:** HQ-139 (decision HQ-138: "go with both"). Resolves HQ-117 by making the embedded Google flow unnecessary.

## Summary

Nobody types a password into an embedded web view any more. The widget gets its usage with an Anthropic OAuth token instead of a claude.ai session cookie, and gets that token one of two ways: by reusing the token Claude Code already keeps in the macOS Keychain (no sign-in at all, one Keychain prompt), or by sending the user to their default browser, where they are usually already signed in to claude.ai and where Google, passkeys and autofill all work, and catching the authorization code on localhost. The v0.3.0 embedded login stays for one release as a hidden fallback.

## Goals

1. First launch on a Mac that has Claude Code: after one Keychain prompt, the ring fills with no sign-in screen at all.
2. First launch anywhere else: one click, "Sign in with your browser", the browser opens on claude.ai, the user approves, the browser tab says "you can close this", the ring fills. Google accounts and passkeys work because the browser does the signing in.
3. The widget refreshes its own token before it expires and never touches Claude Code's refresh token.
4. Sign Out means signed out: the widget's token is deleted, Claude Code's token is no longer used until the user chooses it again, and the fallback web session is wiped.
5. The popover shows which account is signed in (email from the profile endpoint).
6. If Anthropic ever blocks the borrowed OAuth client, the app still has two working paths: Claude Code's token and the embedded login.

## Non-goals

- Console (API) accounts and the `platform.claude.com` authorize page; usage is a consumer-plan feature.
- Multiple accounts on one Mac.
- Removing the embedded login code (v0.5.0, once the browser route has lived in the wild).
- Code signing and notarization (HQ-116).

## Verified facts (spike on 2026-10-12, throwaway script, tokens discarded)

- **Authorize page:** `https://claude.com/cai/oauth/authorize` with `code=true`, `client_id`, `response_type=code`, `redirect_uri=http://localhost:<port>/callback`, `scope=user:profile user:inference`, `code_challenge` (S256), `code_challenge_method=S256`, `state`. It accepted a random localhost port chosen by the app and redirected the browser there with `code` and `state`.
- **Client id:** `9d1c250a-e61b-44d9-88ed-5944d1962f5e`, Claude Code's public OAuth client, read from the Claude Code 2.1.296 binary. Anthropic publishes no third-party client registration. The grant shows in the user's Claude account under Claude Code's name. This is the one accepted risk (HQ-138).
- **Token endpoint:** `POST https://platform.claude.com/v1/oauth/token`, JSON body `{grant_type: "authorization_code", code, state, client_id, redirect_uri, code_verifier}` → 200 `{access_token, refresh_token, expires_in: 28800, refresh_token_expires_in, scope, token_type: "Bearer", token_uuid, account, organization}`. Refresh: same endpoint, `{grant_type: "refresh_token", refresh_token, client_id}` → same shape, new refresh token.
- **Cloudflare:** the token endpoint returns `403` error 1010 for Python's default User-Agent. `ClaudeUsageWidget/0.4.0 (macOS)` passes, as do curl and Safari. Every request carries `User-Agent: ClaudeUsageWidget/<version> (macOS)`, `anthropic-beta: oauth-2025-04-20`, `Accept: application/json`.
- **Usage:** `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <token>` → 200, the same body shape as the claude.ai web endpoint (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `extra_usage`, codenamed nulls, plus a `limits` array). `UsageData.decode` from v0.3.0 reads it unchanged. No token → 401.
- **Profile:** `GET https://api.anthropic.com/api/oauth/profile` → 200 `{account: {uuid, email, display_name, full_name, has_claude_max, has_claude_pro}, organization: {uuid, name, organization_type, rate_limit_tier, ...}}`.
- **Claude Code's credentials:** Keychain generic password, service `Claude Code-credentials`, JSON `{claudeAiOauth: {accessToken, refreshToken, expiresAt (ms since epoch), refreshTokenExpiresAt, scopes, subscriptionType, rateLimitTier}}`. Reading it from another app triggers the macOS Keychain consent prompt once (Allow / Always Allow / Deny); absence returns `errSecItemNotFound` with no prompt.

## Architecture

```
AppDelegate (wiring only)
  ├─ AuthManager                 state machine; picks the identity source; owns sign-in flows
  │    ├─ KeychainTokenStore     the widget's own TokenSet (service io.rsla.ClaudeUsageWidget)
  │    ├─ ClaudeCodeCredentials  read-only view of Claude Code's Keychain item
  │    ├─ OAuthClient            authorize URL, code exchange, refresh (URLSession)
  │    ├─ CallbackServer         NWListener on 127.0.0.1, one GET /callback, 5-minute window
  │    └─ ClaudeAPIClient + LoginWindowController   v0.3.0 web-session fallback, created lazily
  ├─ UsageService                polls one UsageSource every 5 minutes
  │    ├─ OAuthUsageSource       GET /api/oauth/usage with a Bearer token from a TokenProvider
  │    └─ WebSessionUsageSource  GET /api/organizations/{org}/usage through the hidden WKWebView (v0.3.0)
  └─ MenuViewController          popover; sign-in buttons per available route; "Signed in as" subtitle
```

All on the main actor. `UsageData`, `BucketKind`, `RingView`, the row views, `ClaudeAPIError.classify` are unchanged.

### Identity sources and priority

`AuthManager` resolves the identity in this order on launch and on every refresh:

1. **Own OAuth token** in the widget's Keychain item. Expired or within 5 minutes of expiry → refresh. Refresh fails with 400/401 → delete it and continue down the list.
2. **Claude Code's token**, unless the user turned it off (`UserDefaults` `claudeCodeTokenOptOut`) or denied the Keychain prompt earlier (`claudeCodeTokenDenied`, cleared only by the user choosing "Use Claude Code's sign-in" in the popover). Read again on every poll; never refreshed by the widget. Expired and not refreshed by Claude Code → unavailable (the popover says "Open Claude Code once, or sign in with your browser").
3. **Web session** (v0.3.0 cookies), only if the user chose "Sign in inside the app" at some point (`UserDefaults` `webSessionEnabled`). Its state machine is the v0.3.0 `AuthManager` logic, now a `WebSessionAuth` helper inside `AuthManager`.
4. Nothing → `.signedOut`.

### AuthState (revised)

```swift
enum IdentitySource: Equatable { case ownToken, claudeCode, webSession(Organization) }

enum AuthState: Equatable {
    case unknown
    case unreachable
    case signedOut(claudeCodeAvailable: Bool)   // which buttons to show
    case signingIn                               // browser flow in progress, 5-minute window
    case signedIn(IdentitySource, Profile?)      // Profile has email, display name, plan
    case sessionExpired(IdentitySource)
    case noChatOrg                               // web session only
}
```

### Browser sign-in flow (`AuthManager.signInWithBrowser()`)

1. Generate PKCE verifier (32 random bytes, base64url) and challenge (SHA-256, base64url), and a random `state`.
2. Start `CallbackServer` on 127.0.0.1 port 0; it reports the port.
3. Build the authorize URL and open it with `NSWorkspace.shared.open`. State becomes `.signingIn`; the popover shows "Waiting for your browser..." with a Cancel button.
4. The server accepts exactly one `GET /callback`. `state` mismatch → 400 page, keep waiting. Valid → respond with a small HTML page ("Signed in to Claude Usage Widget. You can close this tab.") and resolve the continuation with the code. 5 minutes without a valid callback → cancel, state back to `.signedOut`, popover says "Sign-in timed out".
5. `OAuthClient.exchange(code:verifier:redirectURI:state:)` → `TokenSet` → `KeychainTokenStore.save` → `OAuthClient.profile(token)` → `.signedIn(.ownToken, profile)`.
6. Any failure shows its `userMessage` in the popover and returns to `.signedOut`.

### Token refresh (`TokenProvider`)

`OAuthUsageSource` asks a `TokenProvider` for a bearer token before each request. For the own token: if `expiresAt - now < 300 s`, refresh first (one refresh in flight at a time, callers await the same task). A 401 from the usage endpoint triggers one refresh and one retry; a second 401 is `.sessionExpired(.ownToken)`. For Claude Code's token: read the Keychain item, use `accessToken` if `expiresAt` is in the future, else report unavailable; a 401 means Claude Code's token was revoked → `.sessionExpired(.claudeCode)`.

### Sign out

`signOut()`: delete the own token, set `claudeCodeTokenOptOut = true`, wipe the web-session cookies if that mode was ever used, cancel any browser flow, state `.signedOut(claudeCodeAvailable:)`. The signed-out popover offers:

- **Sign in with your browser** (primary)
- **Use Claude Code's sign-in** (only when the Keychain item exists; clears the opt-out and the denial flag)
- **Sign in inside the app** (small text link; sets `webSessionEnabled`, opens the v0.3.0 login window)

### Popover changes

- Subtitle under the title: `Signed in as <email>` (profile), or `via Claude Code` when the profile call failed, or the org name for the web session as in v0.3.0.
- `.signingIn` state: "Waiting for your browser..." with Cancel.
- `.sessionExpired(source)`: "Session expired" plus the right sign-in button for that source.
- Everything else as v0.3.0.

### Errors

Reuse `ClaudeAPIError`. New cases: `.callbackTimeout`, `.stateMismatch`, `.keychain(OSStatus)`. `userMessage` for each: "Sign-in timed out, try again", "Sign-in response did not match, try again", "Could not read the Keychain (code N)".

## Security

- PKCE S256 and a random `state` on every browser flow; the callback server binds to 127.0.0.1 only, serves one request, and verifies `state` before accepting a code.
- Tokens live only in the Keychain (own item) or are read from Claude Code's item and held in memory; never in UserDefaults, logs, or files.
- Claude Code's refresh token is never used; using it would rotate the token out from under Claude Code.
- Requests go only to `claude.com`, `platform.claude.com`, `api.anthropic.com`.

**Manual (needs a built app and a browser):**

1. Mac with Claude Code, fresh widget: launch → Keychain prompt → Always Allow → ring fills, subtitle "Signed in as <email>". Deny instead → signed-out popover with both buttons.
2. Sign in with your browser, Google account: browser opens, Authorize, tab says close me, ring fills within 3 s.
3. Sign Out → everything gone → "Use Claude Code's sign-in" brings it back without a browser.
4. Edit the own token's `expiresAt` in Keychain Access to the past, refresh → still signed in (token refreshed).
5. Revoke the grant on claude.ai → next poll → "Session expired" with the browser button.

## Rollout

- v0.4.0 tag after the manual pass. Release notes lead with "sign in with your browser" and say the embedded login is still there under "Sign in inside the app".
- Upgrade from v0.3.0: the existing web session keeps working (`webSessionEnabled` is set on first launch when claude.ai cookies exist), so nobody is signed out by the update; the popover offers the browser route next to it.

## Decision log

| Decision | Rationale |
|---|---|
| OAuth token instead of the session cookie | real browser does the sign-in; usage endpoint verified identical |
| Own token before Claude Code's | the user chose the browser route explicitly; Claude Code's is a convenience |
| Never refresh Claude Code's token | rotating it would break Claude Code |
| Honest User-Agent | Cloudflare only blocks the Python default; no need to impersonate anything |
| Callback on localhost with PKCE and state | standard native-app OAuth; the authorize page accepted it in the spike |
| Keep the embedded login for one release | the borrowed client id could be blocked at any time |
| Deny flag remembered | the Keychain prompt must not reappear every 5 minutes |
