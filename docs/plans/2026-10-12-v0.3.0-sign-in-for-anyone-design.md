# v0.3.0: Sign-in for Anyone

**Date:** 2026-10-12
**Status:** Draft, awaiting Rahul's review
**Tracks:** HQ-112 (login window not closing), HQ-115 (auth expiry). New HQ issue to be opened for the feature itself.

## Summary

Make the widget work for any Claude.ai consumer account, not only the one it was built on. Today sign-in is declared by cookie presence, the HTTP status of every API call is thrown away, the first org in the account is assumed to be the chat org, and the usage decoder requires buckets that other plans return as null. Each of those is a way for a new user to see a wrong number, a dead row, or a decode error with no way back to the login window.

This release replaces those four assumptions with verified signals from the API, and makes the popover draw whatever buckets the account actually has. One account per Mac stays. Nothing about distribution (signing, Gatekeeper, Google OAuth) changes.

## Goals

1. A fresh install on any consumer plan (Free, Pro, Max) signs in with email code or password and sees that account's numbers, with no dead rows.
2. An account with several orgs (console org plus chat org, or a Team seat plus personal) gets the chat org, and the one claude.ai last had active when there is more than one.
3. An expired or revoked session is detected on the next poll, shown as "Session expired", and the login window opens once.
4. The login window closes when the API confirms the session, never on URL shape alone.
5. The app reports its real version (About, popover footer, DMG name all agree).
6. Unit tests run in CI on every push, because this Mac has no Xcode.

## Non-goals

- Switching between several Claude accounts on one Mac (declined 2026-10-12; would need macOS 14 per-identifier data stores or cookie extraction).
- A chooser between several chat-capable orgs (the picker rule below decides; a chooser can come later if a real user hits it).
- Google OAuth reliability, code signing, notarization (HQ-116, HQ-117, not code).
- Launch at login, threshold notifications, tooltip (HQ-114, HQ-118, HQ-119).
- Raising the deployment target above macOS 13.

## Verified API facts (checked live on 2026-10-12)

All calls are same-origin `fetch` from a WKWebView that has loaded a `claude.ai` page, so the session cookie rides along. Nothing reads the cookie itself.

**`GET /api/organizations`** returns `200` with a JSON array. Fields used:

| Field | Type | Use |
|---|---|---|
| `uuid` | string | path parameter for usage |
| `name` | string | subtitle when the account has more than one chat org |
| `capabilities` | [string] | `chat` marks a consumer org; `api`, `api_individual` mark the console org |
| `rate_limit_tier` | string | logged for support, not shown (e.g. `default_claude_max_20x`) |
| `plan_display_name` | string or null | not shown (null on the test account) |

The test account has two orgs: a Max chat org and an API console org. Order is not documented, so `orgs.first` is luck.

**`GET /api/organizations/{uuid}/usage`** on the chat org returns `200` with an object. Every bucket is nullable and has the same shape: `{ utilization: number 0..100, resets_at: ISO8601 string, limit_dollars, used_dollars, remaining_dollars, locked_reason }`. Keys seen:

- Fixed buckets: `five_hour`, `seven_day` (present on the test account, assumed present on every plan, decoded as optional anyway)
- Named optional buckets: `seven_day_opus`, `seven_day_sonnet`, `seven_day_oauth_apps`, `seven_day_cowork`
- About fifteen codenamed buckets (`iguana_necktie`, `tangelo`, `nimbus_quill`, ...): feature flags, ignored
- `extra_usage`: `{ is_enabled, monthly_limit, used_credits, utilization, currency, ... }`
- `limits`, `spend`, `seven_day_breakdown`, `weekly_scoped_shares`, `member_dashboard_available`: ignored

`seven_day_sonnet` is null on the test account today, which is why the current popover shows a dead Sonnet row.

**Errors** share one envelope: `{"type":"error","error":{"type":"...","message":"...","details":{"error_code":"..."}},"request_id":"..."}`.

| Situation | Status | `error.type` | `error.details.error_code` |
|---|---|---|---|
| No session, or session invalidated | 403 | `permission_error` | `account_session_invalid` |
| Valid session, console org's usage | 403 | `permission_error` | absent ("Permission denied.") |
| Unknown org uuid | 404 | `not_found_error` | absent |

So "signed out" is **403 with `account_session_invalid`** (plus any 401, defensively), and a bare 403 is a per-org permission problem, not a sign-out.

**Cookies:** `lastActiveOrg` is a readable (non-HttpOnly) cookie whose value is an org uuid. `sessionKey` is HttpOnly; the app never reads it.

## Architecture

Everything stays on the main actor (WebKit requires it). The hidden WKWebView moves out of `AppDelegate` into the API client, and both the auth manager and the usage service talk to the client through a protocol so tests can inject canned responses.

```
AppDelegate (wiring only)
  ├─ ClaudeAPIClient : ClaudeAPI        hidden WKWebView, JS bridge, status classification
  ├─ AuthManager                         state machine, org selection, owns LoginWindowController
  ├─ UsageService                        5-minute polling for one org, decode, expiry detection
  └─ MenuViewController                  popover: dynamic rows, four visual states
```

### ClaudeAPIClient (new file `ClaudeAPIClient.swift`)

```swift
protocol ClaudeAPI: AnyObject {
    func get(_ path: String) async throws -> APIResponse   // throws ClaudeAPIError.transport only
    func lastActiveOrgId() async -> String?                 // reads the lastActiveOrg cookie
    func reset()                                            // after sign-out: reload claude.ai before the next call
}

struct APIResponse { let status: Int; let body: Data }

enum ClaudeAPIError: Error, Equatable {
    case transport(String)      // webView gone, fetch threw, claude.ai did not load in 15 s
    case sessionExpired         // 401, or 403 with error_code account_session_invalid
    case forbidden(String)      // other 403, message from the envelope
    case notFound               // 404
    case server(Int)            // 5xx
    case http(Int)              // anything else non-2xx
    case decode(String)         // body did not match the expected shape

    static func classify(_ response: APIResponse) -> ClaudeAPIError?   // nil for 2xx; pure, unit-tested
}
```

- `get(_:)` first ensures the hidden webView has finished loading `https://claude.ai` (one `WKNavigationDelegate.didFinish`, awaited through a continuation, 15 s timeout). Logged out, claude.ai redirects to `/login`, which is still the same origin, so fetches work.
- The JS bridge takes `path` as a `callAsyncJavaScript` argument (no string interpolation into JS) and returns `JSON.stringify({status, body})`, with `AbortSignal.timeout(15000)` on the fetch.
- `classify` parses the envelope with a small `APIErrorEnvelope: Decodable` and applies the table above.

### Organization (new file `Organization.swift`)

```swift
struct Organization: Decodable, Equatable {
    let uuid: String
    let name: String
    let capabilities: [String]
    let rateLimitTier: String?
    let planDisplayName: String?
    var isChatOrg: Bool { capabilities.contains("chat") }

    /// Prefer the org claude.ai last had active, if it can chat; else the first chat org; else nil.
    static func pickChatOrg(from orgs: [Organization], lastActiveOrgId: String?) -> Organization?
}
```

### AuthManager (rewritten)

```swift
enum AuthState: Equatable {
    case unknown
    case signedOut
    case signedIn(Organization, chatOrgCount: Int)
    case sessionExpired
    case noChatOrg          // signed in, but no org can chat (console-only account)
}

protocol AuthManagerDelegate: AnyObject {
    func authManager(_ m: AuthManager, didChange state: AuthState)
}
```

- `checkAuthStatus()` (launch): `GET /api/organizations` → 2xx → decode `[Organization]` → `pickChatOrg` → `.signedIn` or `.noChatOrg`. `sessionExpired` → `.signedOut` and show the login window (first launch has no session, that is the normal path). `transport` → stay `.unknown`, show "Could not reach claude.ai" in the popover, retry on the next manual refresh. Cookie-presence detection is deleted.
- `verifySession()`: the same call, used by the login window and by expiry recovery.
- `sessionDidExpire()`: called by `UsageService`; sets `.sessionExpired`, shows the login window once. If the user closes it, the state stays `.sessionExpired` and the popover's Sign In button reopens it. No further automatic opens until the next successful sign-in.
- `signOut()`: wipe the default data store (as today), `client.reset()`, state `.signedOut`, show the login window.

### UsageService (revised)

- `init(client: ClaudeAPI, orgId: String)`; no org resolution inside, no cached org id.
- `start()` fetches now and every 300 s; `stop()` invalidates the timer.
- `fetch()`: `GET /api/organizations/{orgId}/usage` → `UsageData.decode` → `didUpdate`. On `ClaudeAPIError.sessionExpired` → `stop()` and `didDetectSessionExpiry`. Any other error → `didFail(error)`, last data stays on screen.

### Models (revised)

```swift
enum BucketKind: String, CaseIterable {
    case session = "five_hour"
    case weeklyAll = "seven_day"
    case weeklyOpus = "seven_day_opus"
    case weeklySonnet = "seven_day_sonnet"
    var label: String   // "Current session", "Weekly (all models)", "Weekly (Opus)", "Weekly (Sonnet)"
    var isWeekly: Bool
}

struct UsageBucket: Equatable {
    let kind: BucketKind
    let percentUsed: Double          // 0.0 ... 1.0
    let resetsAt: Date?
    let lockedReason: String?
}

struct ExtraUsage: Equatable {
    let isEnabled: Bool
    let percentUsed: Double?         // utilization / 100 when present
}

struct UsageData {
    let buckets: [UsageBucket]       // only the buckets the API returned non-null, in BucketKind order
    let extraUsage: ExtraUsage?
    var lastUpdated: Date

    func bucket(_ kind: BucketKind) -> UsageBucket?
    func ringValue(for mode: RingMetricMode) -> Double   // session: five_hour or 0; weekly: max of weekly buckets or 0
    func ringColorState(for mode: RingMetricMode) -> RingColorState
}
```

- `UsageData.decode(from:)` decodes a raw response in which every bucket is `RawBucket?` and `resets_at` is `Date?`. Unknown keys are ignored by `Codable`. The two ISO8601 formatters stay.
- `RingColorState`, `RingMetricMode`, and the display helpers (`resetsInDisplay`, `resetsAtDisplay`) keep their behaviour; they move onto `UsageBucket`.

### LoginWindowController (revised)

- Keeps the WKWebView, popup handling for OAuth, URL KVO, and `didFinish`.
- `isSuccessfulLoginURL` becomes `isCandidateLoginURL` (same rule, same tests). A candidate URL no longer closes the window; it triggers `authManager.verifySession()`.
- While the window is open, `verifySession()` also runs every 2 s as a fallback (the approach built and parked in v0.2.1), so a login that never changes the URL still gets detected.
- The window closes only when `verifySession()` yields `.signedIn` or `.noChatOrg`. Closing the window by hand leaves the state as it was (`.signedOut` or `.sessionExpired`); the popover's Sign In reopens it.

### MenuViewController (revised)

Four visual states, driven by `AuthState` plus the latest `UsageData`:

| State | Body | Footer |
|---|---|---|
| signed in | one `UsageRowView` per bucket, plus "Extra usage" when `extraUsage.isEnabled` and a percent exists; subtitle with the org name when `chatOrgCount > 1` | Sign Out · Quit · vX.Y.Z |
| signed out | existing empty state ("Not signed in") | Sign In · Quit · vX.Y.Z |
| session expired | empty state with "Session expired" / "Sign in again to keep tracking usage" | Sign In · Quit · vX.Y.Z |
| no chat org | empty state with "No Claude plan on this account" / "This account only has API access" | Sign Out · Quit · vX.Y.Z |

- Rows are rebuilt from `data.buckets` on every update (two to five views; no caching needed). The popover's `contentSize` follows the stack's fitting size so two rows and five rows both look right.
- Errors other than expiry keep the rows and write one line into the "Updated ..." label: transport → "Offline or claude.ai unreachable", forbidden → "Permission denied for this org", notFound → "Org no longer exists, sign out and back in", server → "claude.ai error 5xx", decode → "Unexpected response, please report (vX.Y.Z)".
- The ring shows 0 % in every state except signed in.

### AppDelegate (slimmed)

Creates the four components, forwards `AuthState` changes to the popover and ring, starts a `UsageService` on `.signedIn` and stops it on any other state. No WebKit code remains here. The existing ordering rule stays: `setupStatusItem()` runs before anything touches WebKit.

## Testing

**Unit (XCTest, run in CI; locally only once Xcode is installed):**

- `ClaudeAPIErrorTests`: `classify` on fixtures for 200, 401, 403 `account_session_invalid`, 403 "Permission denied.", 404, 500, non-JSON body.
- `OrganizationTests`: `pickChatOrg` when `lastActiveOrg` matches a chat org, when it points at the console org (falls back to the first chat org), when no org can chat (nil), when the list is empty, and when two chat orgs exist (the active one wins).
- `ModelsTests`: `decode` on the real Max 20x shape (sonnet null), a Pro-like shape with opus and sonnet present, a minimal shape with only `five_hour` and `seven_day`, `five_hour` null, `resets_at` null, unknown codenamed keys, `extra_usage` enabled; `ringValue(for:)` when buckets are missing; existing colour and display tests ported to `UsageBucket`.
- `AuthManagerTests`: state transitions with a `FakeClaudeAPI` scripted per call: launch with a valid session, launch with no session, launch with a console-only account, expiry during polling then successful re-login, transport failure stays `.unknown`.
- `UsageServiceTests`: a scripted client returning usage then `account_session_invalid` produces `didUpdate` then `didDetectSessionExpiry` and stops the timer.
- `LoginWindowController.isCandidateLoginURL`: the six existing URL tests, renamed.

**Manual (needs a built app):**

1. Fresh profile (sign out first): launch → login window → email code sign-in → window closes within 2 s of the session existing → rows match claude.ai/settings/usage.
2. Sign Out → empty state → Sign In → same as (1).
3. Expiry: while signed in, invalidate the session from claude.ai (sign out of other sessions in Settings) or wait for natural expiry; within one poll the popover reads "Session expired" and the login window opens once; closing it does not reopen it; signing in resumes polling.
4. A console-only account (if one is available) reads "No Claude plan on this account".

## Decision log

| Decision | Rationale |
|---|---|
| Keep the JS-bridge over `URLSession` | claude.ai's bot protection tends to reject non-browser clients; the bridge already works |
| Prove sign-in by API, not cookies | cookies exist after an abandoned login and after expiry; the API answer is the only truth |
| `account_session_invalid` is the sign-out signal | verified live; a bare 403 means a per-org permission problem |
| Pick the chat org by `lastActiveOrg`, then first chat org | matches what claude.ai shows the user; console orgs always 403 on usage |
| Rows built from returned buckets | the Sonnet bucket is already null for the author; other plans differ again |
| Expiry opens the login window once | Rahul's HQ-115 wording; "once" keeps a menu bar app from nagging |
| Rebuild row views on each update | two to five views, trivially cheap, no stale-view bugs |
| Tests in CI | this Mac has Command Line Tools only; `swiftc -typecheck` works locally, XCTest does not |
