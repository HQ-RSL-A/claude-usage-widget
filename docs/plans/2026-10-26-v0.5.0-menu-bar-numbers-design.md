# v0.5.0: Both Limits in the Menu Bar, Plus UI Fixes

Date: 2026-10-26. Status: approved by Rahul in chat the same day.

## Why

Rahul's ask: "the usage left for session and week being displayed in the widget itself without having to open it." Today the menu bar shows one ring with no number, and a hidden switch picks which limit it follows. To know how much is left he has to click and read the popover. He suggested rotating the two numbers and left the choice open ("or something better if you think").

Success: one glance at the menu bar tells him how much of the session and of the week is left, and which one is getting close.

## Decisions

Rahul's:
- **Numbers count down: what's left.** A fresh session reads 100.
- **Numbers stay readable on any wallpaper** (his message during the build: "use white in the menu bar, coz different wallpapers may cause issues in readability"). The number and the ring's faint track always use the menu bar's own color, white on a dark menu bar like every other icon (black on a light one, where white would vanish). Only the arc turns amber or red. Amber digits on his orange wallpaper were the weak spot.
- **Rings and bars still fill up with use** (his note: "if usage is only 26% left the bar should only show little space on the right side"). So the filled part is what's used, the empty part is what's left, and the number is the size of the empty part. Same fill direction as today.

Mine (approved with the list he saw):
- **Both numbers at once, no rotation.** Two small rings side by side, each with its number inside, like the macOS battery shows "93". Left ring = current session, right ring = week. Rotation was dropped: you wait for the number you want, and motion in the menu bar pulls the eye all day.
- **Each ring's arc is colored on its own** with today's thresholds on the used share: under 60% used normal, 60 to 84% amber (#F59E0B), 85% and up red (#EF4444). In "left" terms: amber at 40 left or fewer, red at 15 left or fewer. The number inside stays in the menu bar's color (see above).
- **The week ring shows the weekly limit closest to running out** (the weekly bucket with the highest used share, among all models, Opus and Sonnet), as the weekly ring mode does today.
- **What's left is `100 - round(used %)`**, clamped to 0...100, so it always adds up to 100 with the "% used" claude.ai shows.
- **The Session/Weekly segmented control goes.** It looks like tabs but only changes the menu bar ring. A gear button in the popover header opens a menu with "Show in Menu Bar" (Session and Week, Session Only, Week Only; default Session and Week) and "Open at Login".
- **No keyboard shortcuts.** The playback promised Cmd-R. A popover from a menu bar app that never activates does not receive key presses (they go to the app in front, where Cmd-R reloads a browser tab), and activating on open would steal focus every time Rahul glances. Dropped; tell Rahul.

## Menu bar

- **Layout per preference.** Session and Week: two rings, about 46 pt wide in total. Session Only or Week Only: one ring, about 24 pt. The width never changes while the preference stays the same: rings are a fixed size whatever the number.
- **Ring:** about 18 pt across, 2.2 pt stroke, track at 25% of the ring color, arc from 12 o'clock clockwise, round caps (same drawing as `RingView` today, thinner). **Number:** SF Pro Rounded bold, about 9 pt for one or two digits, about 7.5 pt for "100", centered. The spike render (`scratchpad/spike/render.swift` in the 2026-10-26 session, not kept) looked right on the real menu bar at these sizes.
- **No data** (checking sign-in, signed out, signing in, session expired, no chat org, unreachable, or signed in with no successful fetch yet): the same layout, every ring an empty track at reduced opacity with a short drawn dash in the middle. Never an empty ring that reads as "0% used". The dash is a drawn line, not a dash character.
- **Stale:** when the newest successful data is older than 15 minutes (three missed polls), draw the rings and numbers at reduced opacity. The numbers stay.
- **A missing bucket keeps its slot** as a no-data ring (dimmed dash), so the width never changes; only that ring is dimmed. Unverified (builder check): whether an idle session, with no messages for over 5 hours, comes back as `utilization: 0` (the ring reads 100, which is right) or as null (the dash). Record what the live endpoint sends the first time it is seen.
- **Colors and appearance.** When every ring is in the normal state, the image is a template image (the system tints it, as today). When any ring is amber or red, the image is not a template; normal rings and their numbers are then drawn in the menu bar's own foreground color for the button's effective appearance (white on a dark menu bar, black on a light one, matching the neighboring icons). Re-render when the button's `effectiveAppearance` changes.
- **Tooltip** (HQ-119): one line per limit, then the age, for example:
  ```
  Current session: 88% left, resets in 3 hr 10 min
  Weekly (all models): 26% left, resets in 3 hr 49 min
  Updated 2 min ago
  ```
  Signed out or other no-data states: one line saying so ("Claude Usage: not signed in", "Claude Usage: checking sign-in", and so on). Kept current at least once a minute.
- **VoiceOver:** the status button gets an accessibility label ("Claude Usage") and a value with the same facts as the tooltip's first lines ("Session 88% left, week 26% left"). Today it reads only "status menu".

## Popover

- **Header:** title and "Signed in as" subtitle as today. On the right, two borderless icon buttons: refresh (SF Symbol `arrow.clockwise`) and settings (SF Symbol `gearshape`), with tooltips "Refresh" and "Settings". While a fetch runs, the refresh button is replaced by a small spinning progress indicator. The custom teenyicons `RefreshButton` (`RefreshIcon.swift`) is removed: it is not a real button (no accessibility, no pressed state).
- **Rows:** label on the left, "88% left" on the right, bar below (fill = used, colored by the used thresholds), detail line below the bar.
  - Labels: "Current session" (was "Current Session"), "Weekly (all models)", "Weekly (Opus)", "Weekly (Sonnet)", "Extra usage".
  - Detail line: a reset less than 24 hours away reads "Resets in 3 hr 10 min" (under an hour: "Resets in 42 min"); further away it reads "Resets Tue 3:00 AM". A bucket at 100% used reads "Limit reached, resets in 1 hr 12 min" (or "Limit reached, resets Tue 3:00 AM"). No reset date, or one in the past: no detail text. Extra usage keeps "Monthly budget".
- **Status line** (replaces the "Updated in 0 seconds" bug):
  - after a successful fetch: "Updated just now" (under a minute), "Updated 3 min ago", "Updated 2 hr ago"
  - while fetching: "Updating..."
  - after a failed fetch with older data on screen: "Couldn't refresh: <reason>. Last updated 12 min ago." (may wrap to two lines)
  - after a failed fetch with nothing on screen: "Couldn't refresh: <reason>"
  - `<reason>` is `ClaudeAPIError.userMessage` as today; a decode error keeps the version suffix
- **Live while open:** reset countdowns and the status line re-render when the popover opens and every 30 seconds while it stays open.
- **Gear menu:** a disabled "Show in Menu Bar" title item, then three radio items "Session and Week", "Session Only", "Week Only", a separator, then "Open at Login" with a checkmark. Choosing a layout re-renders the menu bar at once. Sign Out and Quit stay in the footer.
- Everything else stays: sign-in states and buttons, footer (version, Sign Out, Quit), width 300 pt, outside-click close.

## Staying current

- **Refresh when a limit resets:** after each successful fetch, schedule one extra fetch 10 seconds after the earliest future `resetsAt`. Replace the schedule on every fetch; cancel it when polling stops.
- **Refresh after the Mac wakes:** fetch on `NSWorkspace.didWakeNotification` while signed in.
- Polling stays every 5 minutes. No other new API calls.

## Open at Login (HQ-114)

- `SMAppService.mainApp` (macOS 13+): register when ticked, unregister when unticked. The checkmark reflects `status == .enabled`. If the status is `.requiresApproval`, open the Login Items settings pane (`SMAppService.openSystemSettingsLoginItems()`). On an error, leave it unticked and beep.
- Default off: the app never registers itself.
- Behind a small protocol so tests use a fake and never touch the real login items.
- Unknown: whether `SMAppService.mainApp` accepts this app. Releases are built with `CODE_SIGNING_ALLOWED=NO`, so the app carries only the linker's ad-hoc signature, with no sealed resources and no notarization. Check it on a build made with CI's flags. If it refuses, ship without the menu item and record the finding on HQ-114.

## Preferences

- New UserDefaults key `menuBarShows`: `both` (default), `session`, `week`.
- The old key `ringMetricMode` and `RingMetricMode` are removed; the key is deleted from UserDefaults at launch. It is not migrated: Rahul's saved value is `weekly`, and carrying it over would hide the new layout he asked for.

## Copy rules

- Plain, everyday words (Rahul's standing rule for anything people read in his tools). Menu items in title case, as macOS menus are ("Open at Login", the phrase the Dock uses). Labels and status text in sentence case.
- No en or em dash characters anywhere in the UI. The existing dash placeholders in the popover rows and reset text go.

## Non-goals

- Notifications at a threshold (HQ-118), removing the embedded login (HQ-143), code signing (HQ-116).
- Any change to sign-in, tokens, polling interval or the outside-click close.

## Anti-goals

- Any motion in the menu bar (rotation, pulsing, animated fills).
- A menu bar item that changes width as numbers change.
- Numbers that look current when they are not (stale data at full strength, an empty ring when signed out).

## Testing and verification

- Unit tests (test first, XCTest as today): the left math and rounding; color thresholds; which weekly bucket the week ring uses; reset text at fixed dates and a fixed time zone (under an hour, under a day, over a day, limit reached, missing, past); status line text; tooltip text; the menu bar model for each preference, missing buckets, no-data and stale; popover rows show "N% left" and the new detail text; the segmented control is gone; the gear menu reflects the preference; Open at Login through a fake; the reset-time schedule; the old preference key is removed.
- **Preview mode.** A launch argument `-previewUsage <scenario>` (normal, amber, critical, limit, stale, signed out) feeds made-up usage and skips sign-in entirely: no Keychain read, no WebKit. A new build has a new code identity, so reading the real tokens would raise Keychain prompts that need a human click, and real usage only shows today's state. The scenarios show every state on the real menu bar.
- Drive the built app before calling it done (CLAUDE.md rule), built with CI's signing flags: screenshot the real menu bar in each layout and scenario, open the popover and the gear menu, read the tooltip and the accessibility description through System Events, tick and untick Open at Login and confirm the status, confirm the outside click still closes the popover. - The build shares the installed app's bundle ID and preferences. Quit the installed copy for the drive and reopen it after.
